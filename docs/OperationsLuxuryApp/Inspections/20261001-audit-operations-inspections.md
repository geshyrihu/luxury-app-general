# Análisis Punta a Punta (QA & Arquitectura) - Módulo: Inspection

## Matriz de Vulnerabilidades (Stress Test)

| Proceso / Entidad | Vulnerabilidad Encontrada | Causa Raíz | Solución Propuesta (Código/Patrón) |
| :--- | :--- | :--- | :--- |
| **Backend: Eliminación de Configuración (`DeleteInspectionCondominiumAssetAndRelatedDataAsync`)** | **DESTRUCCIÓN DE AUDITORÍA (CRÍTICO).** Borrar una configuración de inspección borra físicamente todo el historial de ejecuciones pasadas y sus fotos. Rompe la integridad de auditoría histórica. | Uso de `Include(...).ThenInclude(ExecutionItems)` y borrado físico (`DbContext.Remove` + purga de archivos) sin validar si ya existen inspecciones pasadas. | Implementar `Soft-Delete` (IsDeleted) en la configuración O lanzar `BusinessException` (409) si `ExecutionItems.Any()`. Bloquear borrado con historial. |
| **Frontend: Detección de Cambios (`ChangeDetectionStrategy`)** | **SINTAXIS INVÁLIDA / ANTI-PATRÓN.** Más de 100 componentes usan `ChangeDetectionStrategy.Eager`. Angular NO tiene este valor en su enum oficial (`Default` = 0, `OnPush` = 1). Puede causar fallos de compilación u optimización nula. | Confusión conceptual del equipo (mezcla de "Lazy loading" con ChangeDetection). Copiado/pegado masivo. | `sed -i 's/ChangeDetectionStrategy.Eager/ChangeDetectionStrategy.OnPush/g'`. Migrar todo al estándar y manejar Reactividad con Signals. |
| **Backend: Estado y Concurrencia (`CustomerInspectionAppService` & `EquipmentQr`)** | **RACE CONDITIONS.** Dos peticiones simultáneas pueden cambiar el `Status` al mismo tiempo. El código lee memoria (`if status == Completed`) y actualiza sin bloqueos atómicos en DB. | Falta de control de concurrencia optimista (`RowVersion`) o pesimista al actualizar estado de la máquina. | Agregar atributo `[ConcurrencyCheck]` a `Status` o columna `byte[] RowVersion` en EF Core. Capturar `DbUpdateConcurrencyException`. |
| **Frontend: Race Conditions en UI (`resultado-inspeccion.ts`)** | **DESINCRONIZACIÓN DE UI.** Efectos (`effect()`) disparando Promesas `.then()` sin `AbortController`. Si el ID de ruta cambia rápido, la última respuesta puede sobreescribir la correcta. | Uso de estado mutable asíncrono en Signals (`this.data = result`) dentro del efecto sin usar `onCleanup()`. | Pasar a `rxResource` o usar flujos reactivos con RxJS `switchMap` / `takeUntilDestroyed`. Añadir tipado estricto (quitar `data: any`). |
| **Backend: Desempeño / Fuga de Memoria (`InspectionAppService.GetAllAsync`)** | **OUT OF MEMORY (OOM).** `GetAllAsync(customerId)` extrae todas las inspecciones de un cliente sin límite/paginación usando un array gigante. | Retorno plano de `ToListAsync()` sin usar cláusulas `.Take()` o `AsSplitQuery()` para los Includes. | Cambiar firma a `PagedResultDTO`. Inyectar paginación desde el controller y usar `.AsSplitQuery()` para evitar explosión cartesiana. |

> **NOTA (REGLA QA PUNTA A PUNTA):** 
> No se implementarán estas correcciones sin aprobación explícita del usuario. Revisar el reporte y confirmar prioridades para proceder con parche.
